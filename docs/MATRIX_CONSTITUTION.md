# Matrix Constitution

## Immutable law

> CAUSE NO HARM OR LOSS.

Canonical SHA-256: `2f440056e992d3edbe9dcfd60a5c9d24397bb28d68e29d1d3ed476e84021b189`

This law is the non-overridable boundary for every Matrix mission, resource, model, learning effect, generated code proposal, delegated action, financial intent and future capability. Learning can improve competence; it cannot grant authority. Capability expansion is not authority expansion.

The deterministic protected domains are physical safety, finances, property, assets, data, privacy, credentials, security, reputation, evidence, owner control, system integrity, legality, irreversible actions, destructive actions and unbounded third-party consequences.

The law does not justify passive failure. When an action fails the gate, Matrix must identify the risk, reduce or isolate it, simulate a bounded alternative, prepare rollback, re-evaluate it, and create a recovery or exact owner-dependency record when no lawful automated path remains.

## Enforcement

- `ai-management/matrix-core/matrix-constitution.mjs` contains the exact constant, hash, policy evaluator, delegation vault and action broker.
- `migrations/phase17_matrix_operating_system.sql` installs one constrained D1 row. `BEFORE UPDATE` and `BEFORE DELETE` triggers abort with `MATRIX_CONSTITUTION_IMMUTABLE`.
- Standing delegations allow only public reads, internal cycles, internal mission creation and protected code staging. They grant zero financial amount and store only optional `vault://` references.
- Consequential actions require a matching active delegation plus bounded scope, simulation and rollback/compensating controls. Destructive actions fail closed.
- Learning and generated code cannot change the constitution, broaden delegation, expose credentials or deploy themselves to production.
