# ADR 0009: Constitutional Matrix operating system

## Status

Accepted for protected release; production activation requires the canonical budget-gated Cloudflare workflow and a live boot receipt.

## Decision

1. Make `CAUSE NO HARM OR LOSS.` the exact immutable constitutional law. Bind code and D1 to its SHA-256 and abort D1 update/delete attempts.
2. Interpret the law through deterministic physical, financial, property, asset, data, privacy, credential, security, reputation, evidence, owner-control, system-integrity, legal, irreversible, destructive and unbounded-third-party gates.
3. A rejected action generates redesign/retry steps or a recovery mission. Safety is not a silent-stop mechanism.
4. Reuse the existing `matrix_events` spine and scheduled production chain. The Matrix operating cycle runs after Living Matrix and consumes no new cron slot.
5. Store operational work in `matrix_operating_missions` because the existing `matrix_missions` schema is the public member-evidence mission contract. Both remain visible to one director without corrupting either schema.
6. Persist truthful component states, capability snapshots, daily baselines, strict learning effects, boot receipts, watchdog events, delegations and action evaluation receipts.
7. Count learning only when before/after state changes a future decision. Unchanged observations are telemetry.
8. Count new resources only after current policy proof and a real eligible workload benchmark. Count value only after finalized/reconciled external receipts.
9. Capability expansion never grants authority. Standing automation is zero-amount and limited to public reads, internal cycles, internal mission creation and protected staging.
10. Generated code may be tested and staged. It cannot change the constitution, broaden its delegation or self-deploy production code.
11. Consequential actions must flow through `MatrixDelegatedActionBroker`; raw credentials never enter prompts, D1 or action receipts.
12. Scheduled and local-host startup automatically request the constitutional cycle after healthy activation. Live verification requires an immediate boot, measured report, valid D1 constitution and destructive-action rejection.

## Rollback

Phase 17 is additive. Disabling `MATRIX_OPERATING_SYSTEM_ENABLED` stops new cycles without deleting evidence. Removing the Phase 17 Worker route/scheduled call leaves durable records intact. The controlled release captures a D1 time-travel bookmark before migration. The constitution row is intentionally not mutable; rollback uses the protected database bookmark and prior Worker release, never an in-place law edit.

## Truth boundary

Local passing tests mean `WORKING_NOT_LIVE`. Only a completed production boot receipt makes the core loop `LIVE_WORKING`. External resources, funds and model capability are never inferred from configuration or discovery alone.
